# Week 3 · Day 2 — Персонализация: профиль пользователя поверх памяти

## Условие задания

Добавить **персонализацию** поверх модели памяти:

- создать **профиль пользователя**;
- описать **предпочтения** (стиль, формат, ограничения);
- подключить профиль к **каждому** запросу.

Проверить:

- ответы для **разных профилей**;
- что ассистент учитывает предпочтения **автоматически**.

**Результат:** персонализированный агент, адаптированный под пользователя.

---

## Что сделано

За основу взята реализация из [Week 3 · Day 1](../day-1/) — агент с явной
**моделью памяти из трёх слоёв** (краткосрочная / рабочая / долговременная).
Поверх неё добавлен **четвёртый, независимый слой — профиль пользователя
(персонализация)**. Он хранит не *факты* (это дело памяти), а *как именно*
отвечать: роль пользователя и предпочтения по стилю, формату и ограничениям.

Ключевая идея: **память = что знает ассистент, профиль = как он это подаёт.**
Слои независимы — переключение профиля меняет стиль ответов, не трогая память,
а память переживает смену профиля. Профиль **автоматически** попадает в системный
промпт каждого запроса, поэтому предпочтения не нужно повторять в сообщениях.

| Слой | Что хранит | Файл во `filesDir` | Как попадает в запрос |
|------|-----------|--------------------|-----------------------|
| **Профиль (персонализация)** | кто пользователь + стиль / формат / ограничения | `user_profiles.json` | блок «Профиль пользователя» в начале system-prompt |
| Долговременная память | профиль-факты, решения, знания | `long_term_memory.json` | блок памяти в system-prompt |
| Рабочая память | текущая задача + заметки | `working_memory.json` | блок задачи в system-prompt |
| Краткосрочная память | сообщения диалога | `conversation.json` | список `messages` запроса |

Профилей может быть **несколько**; активен ровно один — именно он уходит в
запросы. Переключение активного профиля и даёт проверку «ответы для разных
профилей». При первом запуске засеваются два демонстрационных профиля.

---

## Структура профиля

```
domain/profile/
  UserProfile.kt             # id, name + persona / style / format / constraints
  UserProfileRepository.kt   # порт: набор профилей + активный (loadAll/save/delete/setActive)
```

Поля предпочтений (ровно то, что просило задание):

| Поле | Смысл |
|------|-------|
| `persona` | **кто пользователь** — роль и контекст о нём |
| `style` | **стиль** и тон ответа |
| `format` | **формат** ответа (структура, длина, оформление) |
| `constraints` | **ограничения** — чего не делать / жёсткие требования |

Как и в Day 1, доменная модель — чистый Kotlin (без `@Serializable`); формат
хранения живёт в DTO слоя data (`StoredUserProfile` + `JsonUserProfileRepository`).

---

## Как профиль подключается к каждому запросу

Профиль входит в тот же снимок `MemoryContext`, что и память, и собирается в
системный промпт **в самом начале** — он управляет формой всего ответа, поэтому
должен быть виден модели раньше фактов (`ChatAgent.buildSystemPrompt`):

```
<базовая роль агента>

# Профиль пользователя (персонализация — учитывай всегда и автоматически)
Активный профиль: Новичок
Кто пользователь: Только начинает программировать, термины пока незнакомы.
Стиль ответа: Дружелюбный и ободряющий, простым языком, с аналогиями из жизни.
Формат ответа: Пошагово, развёрнуто; каждый термин поясняй в скобках.
Ограничения: Избегай жаргона без объяснения, …, отвечай по-русски.
Подстраивай каждый ответ под эти предпочтения, даже если пользователь
не повторяет их в сообщении.

# Долговременная память …
# Рабочая память …
```

Поток данных (продолжение схемы Day 1):

```
UI (панель профиля) ── SelectProfile / SaveProfile ──► ChatViewModel
                                                           │ активный профиль
ask(query, history, MemoryContext(longTerm, working, profile)) ─► ChatAgent ─► LLM
```

Пользователь **не** повторяет предпочтения в тексте — агент берёт их из активного
профиля сам. Это и есть «ассистент учитывает автоматически».

## Живой прогон (эмулятор `emulator-5554`)

Оба профиля засеяны при первом запуске, поэтому переключение проверяется без
ввода кириллицы (ограничение `adb`). Один и тот же вопрос —
**`What is a coroutine in Kotlin?`** — задан под двумя профилями.

### Профиль «Senior-разработчик»

> Корутина — это легковесный механизм конкурентности в Kotlin: приостанавливаемая
> функция, которая выполняется асинхронно без блокировки потока. Управляется через
> `CoroutineScope` с заданным контекстом (диспетчер, Job), а suspended-состояние
> компилятор превращает в state machine через CPS-трансформацию.

Технично, сжато, с жаргоном и ссылкой на код — ровно `style`/`format`/`constraints`
этого профиля.

### Профиль «Новичок» (тот же вопрос)

> Привет, Ярослав! Корутина в Kotlin — это «лёгкий поток», который позволяет
> выполнять задачи (например, запрос к серверу) без блокировки основного потока,
> **как официант, обслуживающий несколько столиков одновременно**. В Android она
> нужна, чтобы интерфейс не «зависал» во время долгих операций.

Дружелюбно, с бытовой аналогией, простым языком, без жаргона — предпочтения
«Новичка» учтены **автоматически**, вопрос был идентичным.

### Персонализация и память работают вместе

«Новичок» поздоровался по имени — **«Ярослав»**. Имя пришло из **долговременной
памяти** (слой Day 1), а стиль обращения — из **профиля** (слой Day 2). Слои
независимы и дополняют друг друга: память дала *что знать*, профиль — *как подать*.

## Как запустить

1. Положить ключ в `AgentDemo/.env`: `API_KEY=<ваш_ключ_Z.ai>`.
2. Собрать: `./gradlew :app:assembleDebug`.
3. Установить и запустить `com.example.agentdemo`.
4. Иконка «человек» в шапке → панель профиля. Переключить активный профиль
   (чип «Сделать активным») и задать один и тот же вопрос под разными профилями —
   ответы отличаются по стилю/формату, хотя предпочтения не повторялись в тексте.

## Выводы

- Персонализация легла на архитектуру Day 1 как **ещё один порт + хранилище**,
  без переписывания агента — профиль едет тем же `MemoryContext`, что и память.
- **Память и профиль независимы**: смена профиля не трогает память, память
  переживает смену профиля. Разделение «что знать» (память) и «как подать»
  (профиль) оказалось чистым и наглядным.
- Профиль в system-prompt **каждого** запроса = ассистент учитывает предпочтения
  автоматически; пользователю не нужно повторять их в сообщениях.
- Несколько профилей с переключением дают прямую проверку «ответы для разных
  профилей» — что и подтвердил живой прогон (Senior vs Новичок на одном вопросе).
