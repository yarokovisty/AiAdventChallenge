# Week 2 · Day 1 — Простой агент

## Условие задания

Реализовать простого агента, который:
- принимает запрос пользователя;
- отправляет его в LLM через API;
- получает ответ;
- выводит результат в интерфейсе.

**Важно:**
- агент должен быть **отдельной сущностью**, а не просто одним вызовом API;
- логика запроса и ответа должна быть **инкапсулирована в агенте**.

**Результат:** агент принимает запрос и корректно вызывает LLM через API.

Доп. требования к реализации: Android-приложение, современная архитектура —
**MVI + Clean Architecture + многомодульность**, принципы **SOLID, DRY, KISS, YAGNI**;
дизайн минималистичный, но современный и приятный.

---

## Что сделано

Android-приложение **AgentDemo** (`AgentDemo/`), applicationId `com.example.agentdemo`.
Минималистичный чат: пользователь пишет запрос → агент обращается к LLM (Z.ai) →
ответ появляется в ленте.

Проверено вживую на эмуляторе `emulator-5554` (Medium_Phone_API_36.1),
сборка `assembleDebug` — зелёная, предупреждений нет.

### Живой прогон
Запрос: `Name three Scandinavian capitals in one sentence.`
Ответ агента (по-русски — так задан системный промпт):
> Три столицы Скандинавии — Копенгаген (Дания), Осло (Норвегия) и Стокгольм (Швеция).

## Ключевая идея: агент как сущность, а не вызов API

Главное требование задания — агент не должен быть «тонкой обёрткой над одним
`POST`-запросом». Поэтому в доменном слое есть самостоятельный тип:

```
interface Agent {
    val name: String
    val role: String
    suspend fun ask(query: String, history: List<Message>): AgentReply
}
```

Реализация `ChatAgent` **владеет своей ролью** (системным промптом) и моделью и
**инкапсулирует всю логику** превращения запроса пользователя в обращение к LLM:
сам собирает список сообщений (`system` + история диалога + текущий `user`),
вызывает порт `LlmClient` и очищает ответ. Внешний код (UI, use case) вызывает
только `ask(...)` и ничего не знает о том, как агент общается с моделью.

Поток данных:

```
UI (MVI) → AskAgentUseCase → Agent (ChatAgent) → LlmClient (порт) → Z.ai
```

**Память контекста.** Агент помнит беседу: в `ask` передаётся история прошлых
сообщений, и `ChatAgent` добавляет её в запрос к модели. При этом сам агент — без
скрытого состояния: историей владеет презентационный слой (`ChatState.messages`),
поэтому кнопка «Очистить» просто обнуляет контекст, а агент остаётся чистой
функцией «(запрос, история) → ответ» и легко тестируется.

## Архитектура (Clean Architecture + многомодульность)

| Модуль | Слой | Содержимое |
|--------|------|-----------|
| `:app` | — | `Application`, сборка DI-графа (Koin), `MainActivity` |
| `:core:designsystem` | — | Material3-тема (индиго-акцент, тёмная/светлая) |
| `:domain` | чистый Kotlin | `Agent`, `ChatAgent`, порт `LlmClient`, модели, `AskAgentUseCase` |
| `:data` | data | `ZaiLlmClient` (OkHttp + kotlinx.serialization), DTO, DI-модуль |
| `:feature:chat` | presentation | MVI-контракт, `ChatViewModel`, экран и компоненты |

Зависимости направлены внутрь, к домену:
`app → feature → domain ← data`, а `feature/data/app → core:designsystem`.
Домен не зависит ни от Android, ни от сети — он объявляет порт `LlmClient`,
а реализацию поставляет `:data` (принцип инверсии зависимостей, DIP).

### MVI (`:feature:chat`)
- **State** — `ChatState` (иммутабельный): сообщения, ввод, флаг отправки.
- **Intent** — `ChatIntent` (`InputChanged`, `Send`, `Clear`) — единственный способ
  изменить состояние через `onIntent()`.
- **Effect** — `ChatEffect` (`ShowError`) — одноразовые события.

### UX-детали
- **Ввод над клавиатурой** — строка ввода поднимается над IME через
  `windowInsetsPadding(navigationBars ∪ ime)`; текст всегда виден при наборе.
- **Автоскролл** — при новом сообщении и ответе лента автоматически
  прокручивается к последнему элементу (ключ эффекта — пара «размер списка + флаг
  отправки», чтобы скролл срабатывал и при замене индикатора «печатает» ответом).

### Принципы
- **SOLID** — SRP (транспорт / агент / use case / презентация разнесены),
  DIP (домен зависит от абстракции `LlmClient`, а не от OkHttp).
- **DRY** — тема и компоненты вынесены в `:core:designsystem`.
- **KISS/YAGNI** — без лишних слоёв: один экран (навигация не нужна),
  агент без истории, типографика дефолтная.

## Технологии

- **Kotlin 2.3.20**, **AGP 9.0.1** (встроенная поддержка Kotlin), **Gradle 9.1**.
- **Jetpack Compose + Material3**, Compose BOM 2026.03.01.
- **DI — Koin** (чистый runtime-DI без кодогенерации; устойчив к «будущим»
  версиям Kotlin/AGP, где Hilt на KSP/kapt часто ломает сборку).
- **Сеть — OkHttp + kotlinx.serialization** (типизированный JSON вместо ручного
  `org.json`; порт `LlmClient` скрывает транспорт от домена).
- **Coroutines + Flow**.

### API Z.ai
- Эндпоинт: `https://api.z.ai/api/coding/paas/v4/chat/completions` (OpenAI-совместимый).
- Модель: `glm-4.6`, `thinking: disabled` (нужен прямой ответ без reasoning-трейса).
- Ключ берётся из корневого `.env` (`API_KEY`) → `BuildConfig.ZAI_API_KEY` слоя `:data`,
  так секрет не протекает в UI и домен.

## Как запустить

1. Положить ключ в `AgentDemo/.env`: `API_KEY=<ваш_ключ_Z.ai>`.
2. Собрать: `./gradlew assembleDebug`.
3. Установить на эмулятор/устройство и запустить `com.example.agentdemo`.

## Выводы

- «Агент как сущность» проще всего выразить через доменный интерфейс `Agent` +
  порт `LlmClient`: вся логика «запрос → LLM → ответ» живёт в одном месте и
  тестируется с подменным клиентом, а UI об этом ничего не знает.
- На bleeding-edge версиях (Kotlin 2.3.20 / AGP 9) **Koin** оказался надёжнее Hilt
  именно из-за отсутствия кодогенерации.
- AGP 9 **встроил** поддержку Kotlin: плагин `org.jetbrains.kotlin.android` в
  Android-модулях больше не нужен (и его наличие ломает сборку).
