# Week 2 · Day 2 — Сохранение контекста агента

## Условие задания

Добавить агенту **сохранение контекста** между запусками:
- хранить историю диалога (`messages`) в JSON или SQLite;
- при перезапуске агента загружать историю обратно;
- продолжать диалог так, будто агент не выключался.

Проверить на практике: начать диалог → перезапустить приложение → продолжить
диалог и убедиться, что агент помнит прошлые сообщения.

**Результат:** агент, который сохраняет и восстанавливает контекст между запусками.

---

## Что сделано

За основу взята реализация агента из [Week 2 · Day 1](../day-1/) (Android-приложение
**AgentDemo**, Clean Architecture + MVI + многомодульность, DI на Koin). Проект
скопирован в `AgentDemo/` этого дня и дополнен слоем **персистентности истории**.

Хранилище — **JSON-файл** во внутренней памяти приложения
(`filesDir/conversation.json`), сериализация через уже подключённый
`kotlinx.serialization`. SQLite/Room сознательно не брали: Room тянет
KSP-кодогенерацию — ровно то, от чего в проекте ушли (Koin вместо Hilt на
bleeding-edge Kotlin 2.3.20 / AGP 9). JSON даёт ноль новых зависимостей, прост в
отладке и полностью покрывает один диалог (принципы KISS/YAGNI).

### Живой прогон (эмулятор `emulator-5554`)

1. Запрос: `My name is Yaroslav and my favorite color is indigo. Please remember this.`
   Ответ агента: «Здравствуйте, Ярослав! Запомнил…».
2. Содержимое `files/conversation.json` после обмена:
   ```json
   [
     {"role":"USER","text":"My name is Yaroslav and my favorite color is indigo. Please remember this."},
     {"role":"AGENT","text":"Здравствуйте, Ярослав! Запомнил в рамках этого диалога: ваше любимое цвет — индиго. …"}
   ]
   ```
3. `adb shell am force-stop com.example.agentdemo` — **полная остановка процесса**.
4. Повторный запуск — лента диалога восстановилась из файла.
5. Новый запрос (без контекста в самом сообщении): `What is my name and my favorite color?`
   Ответ агента:
   > Ваше имя — Ярослав, а ваш любимый цвет — индиго.

Последний шаг доказывает сквозную работу: история не просто рисуется на экране, а
**снова уходит в LLM как контекст** — агент «продолжает», будто не выключался.

Сборка `assembleDebug` — зелёная.

## Как устроено сохранение контекста

Главный приём — не хранить историю в агенте и не завязывать домен на файлы/БД, а
ввести **порт хранилища** по тому же принципу инверсии зависимостей, что и
`LlmClient`:

```
interface ConversationRepository {
    suspend fun load(): List<Message>
    suspend fun save(messages: List<Message>)
    suspend fun clear()
}
```

- **Домен** объявляет только контракт (`:domain`), ничего не зная про JSON и Android.
- **Data** поставляет реализацию `JsonConversationRepository` (`:data`): пишет/читает
  `List<StoredMessage>` (сериализуемый DTO) в `filesDir/conversation.json` на
  `Dispatchers.IO`. Запись — перезапись всего списка: для единственного диалога это
  проще и надёжнее инкрементального append.
- **Presentation** (`ChatViewModel`) получает порт через Koin и:
  - в `init` вызывает `load()` и восстанавливает `ChatState.messages`;
  - сохраняет историю **дважды** на отправке — сразу с репликой пользователя (чтобы
    пережить kill во время запроса к сети) и после ответа агента;
  - на «Очистить» вызывает `clear()`.

Поток данных (дополнен хранилищем):

```
UI (MVI) → ChatViewModel ──ask──→ AskAgentUseCase → Agent → LlmClient → Z.ai
                         └─save/load─→ ConversationRepository → conversation.json
```

Агент при этом остаётся **чистой функцией** «(запрос, история) → ответ» без скрытого
состояния: памятью владеет presentation-слой, а долговечность ей даёт порт
хранилища. Так требование «агент как сущность» из Day 1 не нарушено.

## Изменения относительно Day 1

| Файл | Что изменилось |
|------|----------------|
| `domain/.../conversation/ConversationRepository.kt` | **новый** порт хранилища истории |
| `data/.../conversation/StoredMessage.kt` | **новый** `@Serializable` DTO + маппинг в доменный `Message` |
| `data/.../conversation/JsonConversationRepository.kt` | **новая** реализация порта на JSON-файле |
| `data/.../di/DataModule.kt` | регистрация `ConversationRepository` (через `androidContext()`) |
| `data/build.gradle.kts` | добавлен `koin-android` (нужен `androidContext()` для `filesDir`) |
| `feature/chat/.../di/ChatModule.kt` | прокидывание репозитория в `ChatViewModel` |
| `feature/chat/.../ChatViewModel.kt` | загрузка истории в `init`, автосохранение на отправке, `clear()` на очистку |

Домен остался чистым Kotlin: `Message`/`Role` **не** помечены `@Serializable` —
формат хранения живёт в DTO слоя data.

## Как запустить

1. Положить ключ в `AgentDemo/.env`: `API_KEY=<ваш_ключ_Z.ai>`.
2. Собрать: `./gradlew assembleDebug`.
3. Установить и запустить `com.example.agentdemo`.
4. Проверка контекста: написать сообщение → убить приложение (свайпом из «недавних»
   или `adb shell am force-stop com.example.agentdemo`) → снова открыть → лента на
   месте, агент помнит сказанное ранее.

## Выводы

- Персистентность контекста чисто ложится на существующую архитектуру: ещё один
  **порт в домене** (`ConversationRepository`) + реализация в `:data`, без правок
  самого агента. Это прямое продолжение идеи «домен зависит от абстракций».
- **JSON-файл** оказался достаточным и самым дешёвым вариантом (ноль кодогенерации),
  что согласуется с выбором Koin вместо Hilt в этом проекте.
- Двойное сохранение (с репликой пользователя до ответа модели) делает историю
  устойчивой к убийству приложения прямо во время сетевого запроса.
