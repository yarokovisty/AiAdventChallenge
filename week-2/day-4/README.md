# Week 2 · Day 4 — Управление контекстом (сжатие истории)

## Условие задания

Реализовать механизм управления контекстом диалога:

- хранить последние **N** сообщений «как есть»;
- остальное заменять на **summary** (например, каждые ~10 сообщений);
- хранить summary **отдельно** и подставлять его в запрос вместо полной истории.

Сравнить:

- качество ответов **без сжатия**;
- качество ответов **со сжатием**.

**Результат:** агент, который по мере роста диалога сворачивает старые сообщения
в краткое содержание, не раздувая контекст — и при этом не теряет нужных фактов.

## Как устроен механизм

Решение «что уйдёт в модель» принимает `ContextCompressor` на каждой отправке
(значения по умолчанию `keepLastN = 4`, `summarizeEveryM = 6`):

```
foldable = history.size - keepLastN              // что в принципе можно свернуть
если (foldable - memory.foldedCount >= summarizeEveryM):
    newlyFolded = history[memory.foldedCount ..< foldable]
    summary = summarizer.summarize(memory.summary, newlyFolded)   // инкрементально
    foldedCount = foldable
tail = history.drop(foldedCount)                 // хвост «как есть»
→ в модель: systemPrompt + [summary как system-сообщение] + tail + query
```

Три важных свойства:

1. **Последние N — дословно.** Хвост `tail` всегда содержит свежие реплики без искажений.
2. **Инкрементальный summary.** Summary не пересчитывается заново каждый раз — в него
   лишь *вплетается* очередная пачка старых сообщений. Ре-саммари срабатывает
   пачкой раз в `M` сообщений (ровно идея «каждые 10 сообщений» из задания).
3. **Summary хранится отдельно.** `agent_memory.json` лежит рядом с
   `conversation.json`, но независимо от него — и подставляется в запрос вместо
   свёрнутой части истории.

Агент (`ChatAgent`) остаётся **чистой функцией** «(запрос, хвост, summary) → ответ»:
если summary задан, он уходит в модель отдельным `system`-сообщением
(«Краткое содержание предыдущей части диалога…»). Режим без сжатия — это просто
`summary = null` и `tail = вся история`.

Поток данных:

```
UI (MVI) → ChatViewModel ──ask──→ AskAgentUseCase ──→ ContextCompressor ──→ Summarizer → Z.ai
                         │                        └──→ Agent → LlmClient → Z.ai
                         └─save/load─→ ConversationRepository → conversation.json
                         └─save/load─→ AgentMemoryRepository  → agent_memory.json
```

В интерфейсе добавлены: **тумблер сжатия** в шапке (значок ⯮), **полоса-статус** с
режимом и метриками последней отправки и **просмотр текущего summary** по тапу.

## Живой прогон (эмулятор `emulator-5554`)

> Промпты на английском: ввод кириллицы через `adb` на эмуляторе не проходит, а
> механизм от языка не зависит (эвристика токенов считает и латиницу, и кириллицу).
> Ответы агента — на русском, как и задано системным промптом.

Диалог наращивался короткими сообщениями. Полоса-статус показывала, что уходит в
модель **со сжатием** (`keepLastN = 4`, `summarizeEveryM = 6`):

| Отправка | Размер истории | Статус | ≈ токенов контекста |
|---------:|---------------:|--------|--------------------:|
| 1 (факты: имя/цвет/кот) | 0 | Отправлено 0 реплик | 29 |
| 2 | 2 | Отправлено 2 реплик | 137 |
| 3 | 4 | Отправлено 4 реплик | 211 |
| 4 | 6 | Отправлено 6 реплик | 234 |
| 5 | 8 | Отправлено 8 реплик | 314 |
| **6 (вопрос на вспоминание)** | **10** | **Отправлено 4 реплик + summary (свёрнуто 6)** | **280** |

На 6-й отправке сработало сворачивание: 6 самых старых реплик заменены на summary,
дословно ушли только последние 4.

**Проверка качества.** Шестым сообщением был заданы вопрос
`Remind me: what is my name, my favorite color, and my cat's name?` — а факты
(имя/цвет/кот) из первого обмена к этому моменту **уже свёрнуты в summary** и в
«сыром хвосте» их нет. Ответ агента:

> Конечно, Ярослав! 🎨 Твой любимый цвет — **индиго**, а кота зовут **Барсик**.

Значит, факты агент взял именно из summary.

**Содержимое summary** (по тапу на полосу-статус / из `agent_memory.json`):

```
- Пользователя зовут Ярослав; любимый цвет — индиго; кот — Барсик (запомнено в рамках текущего диалога).
- Ассистент рассказал факт об осьминогах: у них три сердца; главное останавливается при плавании, поэтому они ползают.
- Вычисление: 17 × 3 = 51.
```

**Summary хранится отдельно** — в файловой системе приложения два независимых файла:

```
-rw------- 475  agent_memory.json   {"summary":"- Пользователя зовут Ярослав; …","foldedCount":6}
-rw------- 2258 conversation.json   [полная лента всех сообщений]
```

## Сравнение: со сжатием vs без сжатия

Тот же вопрос на вспоминание задан в обоих режимах (переключается тумблером в шапке):

| Режим | Что ушло в модель | ≈ токенов | Ответ |
|-------|-------------------|----------:|-------|
| **Сжатие ВКЛ** | 4 реплики + summary | **280** | верно: Ярослав / индиго / Барсик |
| **Сжатие ВЫКЛ** | 12 реплик (вся история) | **469** | верно: Ярослав / индиго / Барсик |

**Вывод по качеству:** на этой длине диалога оба режима отвечают одинаково верно —
т.е. сжатие **не ухудшило качество**, хотя факт был «спрятан» в summary. При этом
контекст со сжатием почти вдвое меньше и, главное, **не растёт линейно** с длиной
диалога: хвост всегда ограничен `keepLastN + M`, тогда как без сжатия каждая новая
реплика добавляется в запрос навсегда. Именно там, где без сжатия контекст рано или
поздно переполнит окно модели, сжатие удержит его в границах — ценой риска, что
summary потеряет мелкую деталь (поэтому самые свежие реплики мы и храним дословно).

## Как запустить

1. Положить ключ в `AgentDemo/.env`: `API_KEY=<ваш_ключ_Z.ai>`.
2. Собрать: `./gradlew assembleDebug`.
3. Установить и запустить `com.example.agentdemo`.
4. Проверка сжатия: вести диалог, где важный факт назван в начале; после ~5 обменов
   полоса-статус покажет «… + summary (свёрнуто N)». Задать вопрос по раннему факту —
   агент ответит из summary. Тумблер в шапке переключает режим для сравнения.

## Выводы

- Управление контекстом чисто ложится на архитектуру day-1/2: ещё один **порт**
  (`Summarizer`, `AgentMemoryRepository`) + доменный сервис (`ContextCompressor`),
  без правок самого агента. Агент по-прежнему не хранит состояние.
- **Инкрементальный summary** (сворачиваем пачками, а не пересчитываем всё) экономит
  вызовы модели: лишний запрос на сжатие случается раз в `M` сообщений, а не каждый ход.
- **Главный эффект сжатия — не экономия на коротком диалоге, а ограниченность
  контекста на длинном.** Хвост фиксированной длины + компактный summary не дают
  запросу расти бесконечно; качество при этом сохраняется, пока summary удерживает
  ключевые факты (за это отвечает и низкая температура суммаризатора, и то, что
  самые свежие реплики остаются дословными).
