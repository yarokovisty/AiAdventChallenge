# Week 5 · Day 1 — RAG: Document Indexing

## Условие задания

Собрать **локальный индекс документов** с эмбеддингами и метаданными. Сравнить
две стратегии разбиения документов на чанки:

- по **фиксированному размеру**;
- по **структуре** документа.

**Результат:** скрипт [`build_index.py`](build_index.py), который из корпуса
`documents/*.md` строит два локальных индекса (`index/fixed.json`,
`index/structured.json`) — текст чанка + метаданные + эмбеддинг — и на тестовых
запросах с эталонными секциями показывает разницу стратегий.

---

## Что сделано

| Файл | Роль |
|------|------|
| [`build_index.py`](build_index.py) | Пайплайн: корпус → чанкинг (2 стратегии) → эмбеддинги → локальные индексы → smoke-поиск → отчёт-сравнение |
| [`documents/`](documents/) | Корпус: 5 Markdown-документов «база знаний курса» (промптинг, агенты, контекст, MCP, RAG), ~18,8 тыс. символов, с выраженной иерархией заголовков и секциями разной длины |
| `index/fixed.json`, `index/structured.json` | Локальные индексы (генерируются, ~280 КБ каждый) |

```
documents/*.md ──► chunk_fixed()      ──► чанк + метаданные (doc, позиция, длина)
                └► chunk_structured() ──► чанк + метаданные (+ путь заголовков)
                              │
                              ▼
                     эмбеддинг-провайдер (Z.ai API → фолбэк локальная e5)
                              │
                              ▼
                index/fixed.json + index/structured.json
                              │
                              ▼
        проверка: 6 запросов с эталонами → косинусная близость → top-3 → hit@k
```

### Стратегии чанкинга

**fixed** — классический baseline: текст режется на куски **~600 символов** с
перекрытием **100 символов** (overlap страхует факты на границах). Границы слов
не ломаем, но на предложения и заголовки не смотрим вовсе — честный «фиксированный
размер».

**structured** — по структуре документа: markdown раскладывается на **секции по
заголовкам** (H1–H6), внутри секции абзацы жадно склеиваются до целевого размера
(~600 симв.), абзац длиннее жёсткого потолка (900) режется **по границам
предложений**, блоки кода атомарны. Путь заголовков («документ > раздел >
подраздел») пишется и **первой строкой в текст чанка** (эмбеддинг знает, о каком
разделе речь), и **в метаданные**.

### Эмбеддинги: попытка Z.ai → локальная модель

Провайдер выбирается автоматически:

1. **Z.ai embeddings API** (`api.z.ai/api/paas/v4/embeddings`, модель
   `embedding-3`) — если задан `ZAI_API_KEY`. **На глобальном endpoint Z.ai
   embeddings-моделей нет**: live-проверка вернула `1211 Unknown Model`, а
   `GET /models` отдаёт только чат-модели GLM (подтверждается issue
   [z-ai-sdk-python#67](https://github.com/zai-org/z-ai-sdk-python/issues/67)).
   Скрипт печатает причину и переходит к фолбэку — код готов к тому дню, когда
   API появится.
2. **Локальная модель** [`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small)
   (384 измерения) — полностью офлайн после первой загрузки (~470 МБ в кэш
   HuggingFace). Особенность e5: запросы и документы должны кодироваться с
   префиксами `query:` / `passage:` — без них качество проседает.

Оба индекса строятся **одним провайдером** — сравнение стратегий честное.

### Формат индекса

```json
{
  "strategy": "structured",
  "params": { "target": 600, "hard_max": 900, "boundaries": "заголовки → абзацы → предложения" },
  "embedding": { "provider": "local-e5", "model": "intfloat/multilingual-e5-small", "dim": 384 },
  "documents": [ { "name": "01-prompting-basics.md", "sha1": "f8b6…", "chars": 4154 } ],
  "chunks": [
    {
      "id": "structured-0009", "doc": "01-prompting-basics.md", "pos": 9, "chars": 469,
      "heading_path": ["Основы LLM и промптинг", "Типичные ошибки новичков"],
      "text": "Основы LLM и промптинг > Типичные ошибки новичков\n\nЧаще всего…",
      "vector": [0.019437, -0.033559, -0.060835, "…всего 384 числа…"]
    }
  ]
}
```

## Результат сравнения

| Метрика | fixed (600 симв. / overlap 100) | structured (по заголовкам) |
|---|---|---|
| Чанков из 5 документов | 39 | 42 |
| Размер чанка, симв. (мин / средн / макс) | 129 / 563 / 599 | 143 / 476 / 956* |
| Разрезано посреди предложения | **31 (79%)** | **0 (0%)** |
| Метаданные чанка | doc, позиция, длина | + путь заголовков |
| **hit@1** — нужный документ на 1-м месте | 5/6 | **6/6** |
| **hit@3** — нужный документ в топ-3 | 6/6 | 6/6 |
| top-1 попал в **эталонную секцию** | 0/6 (нечем измерить — метаданных нет) | **6/6** |

\* 956, а не 900: жёсткий потолок применяется к контенту секции, поверх
добавляется строка-«паспорт» с путём заголовков.

Самый показательный провал fixed — запрос Q5 («зачем резать документы по
заголовкам, а не по количеству символов?»): top-1 уехал в документ про промптинг
(чанк со словами «структура» и «формат» без контекста раздела), тогда как
structured дал точное попадание в секцию «Чанкинг документов». Ещё один
эффектный недостаток fixed виден прямо в сниппетах поиска: чанки выглядят как
«…ограничение очевидно: stdio работает только на одной машине, удалённо такой
сервер не поднять. ### Транспорт Streamable HTTP…» — обрывок одной темы,
склеенный с началом другой, с сырым markdown посередине.

## Как запустить

```bash
cd week-5/day-1
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt   # Windows
copy .env.example .env        # вписать ZAI_API_KEY (не обязателен: без него сразу локальная модель)
venv\Scripts\python.exe build_index.py                       # сборка индексов + отчёт + тесты
venv\Scripts\python.exe build_index.py --query "какие транспорты бывают у MCP"
```

Первый запуск скачивает модель e5 в кэш HuggingFace (~470 МБ), дальнейшие —
офлайн, вся индексация и поиск локальные.

## Выводы

- **Структурный чанкинг выигрывает по всем метрикам**: те же ~600 символов на
  чанк, но ни одного разреза посреди предложения (против 79% у fixed), точность
  top-1 по секциям 6/6 и ни одного промаха по документу. На незнакомом корпусе
  разрыв был бы ещё заметнее: наш корпус маленький, и даже «обрывки» часто
  дотягивают до нужного документа.
- **Метаданные — это односторонняя дверь**: путь заголовков нельзя восстановить
  постфактум для уже нарезанных fixed-чанков. Что положили в индекс, то и будет
  available для фильтрации, атрибуции и цитирования — enriched на этапе
  индексации.
- **Провал fixed показателен**: на «мета-вопросе» про сам чанкинг top-1 уехал в
  другой документ — обрывки без контекста раздела размывают эмбеддинг. overlap
  страхует границы, но не добавляет семантической целостности.
- **У Z.ai нет embeddings API на глобальном endpoint** (1211 Unknown Model,
  `/models` — только чат-модели GLM; см. issue в их SDK). Локальная
  e5 с префиксами `query:`/`passage:` — рабочая офлайн-альтернатива, а абстракция
  провайдера в коде включит Z.ai одной строкой, если API появится. Ключ Z.ai из
  `.env` пригодится в следующих днях недели — для генерации ответов по найденным
  чанкам.
